# Vibe Coding 过程记录

## 第一轮：定义可交付问题

目标不是制作通用聊天机器人，而是让招聘方在无需安装环境的情况下完成一次财务分析。

关键约束：

- 打开后自动展示示例数据。
- 不要求登录、API Key 或远程服务。
- 财务计算必须确定、可测试，不能由语言模型心算。
- 同时覆盖 Python、MySQL、前端展示和部署证据。

## 第二轮：拆分计算与展示

将财务公式放入独立 `finance_engine.py`，前端读取由 Python 生成的数据文件。这样可以：

1. 用 Python 单元测试验证核心指标。
2. 让静态页面保持零运行时依赖。
3. 避免为了在线演示引入不稳定的后端环境。

纠错记录：生成演示数据时发现健康信号读取了错误的字段层级。修正为从最新财年记录读取经营现金流，并重新运行测试与数据生成脚本。

## 第三轮：完善分析闭环

首版只包含历史指标。为满足“基础财务分析”和“业务抽象”要求，增加：

- 可解释的风险规则及建议核查动作。
- 收入增速、毛利率和费用率情景预测。
- 三年后净利润敏感性矩阵。
- CSV 导入和即时重新计算。

所有数字计算保持确定性。前端只负责输入、计算和呈现，不生成未经核验的财务事实。

## 第四轮：从可运行到可展示

补充 README、财务公式、MySQL 表结构、测试、GitHub Pages 部署和演示脚本。展示验证包括桌面、移动端、控制台、关键交互与截图。

## 面试可讲要点

- 为什么不用 LLM 直接计算财务指标。
- 为什么静态前端配合 Python 数据生成更适合快速发布。
- 风险阈值为什么需要按行业配置。
- 如何用公式测试验证 AI 生成的代码。
- 简化预测模型遗漏了哪些真实财务因素。
